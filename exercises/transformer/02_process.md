# 02_causal_self_attention.py 详细流程图解

> 配套脚本:`exercises/transformer/02_causal_self_attention.py`
> 相比 01 多了四个新东西:**PyTorch `nn.Module` 封装、batch 维度、因果掩码、输出投影 W_o**。

## 全景:数据流(和 01 同骨架,多了 mask 和 W_o)

```
   tokens ["The","cat","sat","on","the","mat"]
        │  ① 查表 (dict 模拟 nn.Embedding)
        ▼
   x  (B=1, T=6, d=16)        ← 多了 batch 维 B
        │
        │  ② W_q / W_k / W_v  (nn.Linear, 无 bias)
        ├──────────────┬──────────────┐
        ▼              ▼              ▼
   Q(1,6,16)      K(1,6,16)      V(1,6,16)
        │              │              │
        └──────┬───────┘              │
               │ ③ scores = Q·Kᵀ/√d   │
               ▼   (1,6,6)            │
         scores (1,6,6)               │
               │ ★④ 因果掩码          │
               │   未来位置 ← -inf     │
               ▼                      │
         softmax → attn (1,6,6)       │
               │   上三角全为 0        │
               └──────────┬───────────┘
                          │ ⑤ out = attn·V
                          ▼
                     (1,6,16)
                          │ ⑥ W_o 输出投影  ← 01 没有
                          ▼
                     out (1,6,16)
```

| 对比 | 01_attention_scratch | 02_causal_self_attention |
|------|---------------------|--------------------------|
| 框架 | numpy 裸写 | PyTorch `nn.Module` |
| 形状 | `(T, d)` 无 batch | `(B, T, d)` 有 batch |
| 掩码 | 无 | ★ 因果掩码 |
| 输出投影 | 无 | ★ `W_o` |
| 矩阵 | 手动 `X@W` | `nn.Linear`(可训练) |

---

## 第①步:查表 + batch 维 (100–119 行)

和 01 一样查表,**唯一区别**是末尾 `.unsqueeze(0)` 加了一个 batch 维:

```
  x_2d (T=6, d=16)  ──unsqueeze(0)──►  x (B=1, T=6, d=16)

  为什么要 B?  真实训练一次喂多个序列(一个 batch),
              所有运算都按 batch 并行 → 形状统一带 B 打头。
```

`The`/`the` 仍然同向量(`x[0,0]==x[0,4]`)。

---

## 第②~③步:投影 + 打分(和 01 同理,带 batch)

```
  Q @ K.transpose(-2,-1)
  (1,6,16) @ (1,16,6) = scores (1,6,6)
            └ 只转最后两维, batch 维 B 不动 ┘
```

`transpose(-2,-1)` 而不是 `.T`,就是因为有了 batch 维——只想转 `T` 和 `d` 两维,不动 `B`。

---

## ★ 第④步:因果掩码(本篇核心,44–83 行)

**动机:** LLM 训练做"预测下一个词"。token i 预测时**只能看 0..i,不能偷看未来 i+1..**。否则训练作弊、推理就废。

**掩码怎么造的(60行):** `torch.tril(torch.ones(T,T))` —— 下三角全 1,上三角全 0:

```
        k=0  k=1  k=2  k=3  k=4  k=5
  q=0 │  1    0    0    0    0    0 │  The 只能看自己
  q=1 │  1    1    0    0    0    0 │  cat 看 0~1
  q=2 │  1    1    1    0    0    0 │  sat 看 0~2
  q=3 │  1    1    1    1    0    0 │
  q=4 │  1    1    1    1    1    0 │
  q=5 │  1    1    1    1    1    1 │  mat 全看
        1=允许    0=禁止(未来)
```

**怎么用(80行 `masked_fill`):** 在 softmax **之前**,把 mask==0 的位置塞 `-inf`:

```
  scores                         masked_fill(mask==0, -inf)
  [ 2.1  0.3  1.5  0.8 ...]  ──►  [ 2.1  -inf -inf -inf ...]  (q=0 行)
                                         ↑ 未来位置全变 -inf
            │ softmax
            ▼
  [ 1.00  0.00 0.00 0.00 ...]   ← exp(-inf)=0, 未来权重精确为 0
```

**为什么用 -inf 不用 0?**

| 填充值 | softmax 里 exp(·) | 结果 |
|--------|------------------|------|
| `-inf` | `exp(-inf)=0` | 权重精确 0 ✓ 看不见未来 |
| `0` | `exp(0)=1` | 反而分了权重过去 ✗ |

> 关键顺序:**mask 在 softmax 之前**。因为要靠 `exp(-inf)=0` 让那一项在归一化时贡献为 0,且其余位置重新归一后仍然和为 1。

掩码注册成 `buffer`(61行)而非参数:它**不参与训练**(没有梯度),但会跟着 `model.to(device)` 一起搬到 GPU。

---

## 第⑤~⑥步:加权 V + 输出投影 (85–90 行)

```
  out = attn @ V        (1,6,6)@(1,6,16) = (1,6,16)
  out = self.W_o(out)   再过一层 Linear, 形状不变 (1,6,16)
```

**W_o 的作用(01 没有):** attention 把各 token 的 V 混合后,再用一个可学习的线性层"重新整理"一遍输出空间。多头注意力里它还负责把多个头拼接后融合——这里单头先打基础。

---

## 对照实验:有掩码 vs 无掩码 (121–155 行)

脚本特意跑两遍、复用同一组权重,直接看掩码的效果:

```
  无掩码 attn (作弊版)            有掩码 attn (LLM 标配)
        k→                            k→
  q  ┌─────────────┐            q  ┌─────────────┐
     │ ▓ ▓ ▓ ▓ ▓ ▓ │  每行都满      │ ▓ · · · · · │  上三角
     │ ▓ ▓ ▓ ▓ ▓ ▓ │              │ ▓ ▓ · · · · │  全 0.000
     │ ▓ ▓ ▓ ▓ ▓ ▓ │   ──►        │ ▓ ▓ ▓ · · · │
     │ ▓ ▓ ▓ ▓ ▓ ▓ │              │ ▓ ▓ ▓ ▓ · · │
     └─────────────┘              └─────────────┘
   能看到未来→训练作弊         只能看左侧→正确
```

验证(154行):有掩码时上三角权重之和 `triu(diagonal=1).sum() == 0`。

## 一句话总结

因果自注意力 = **01 的自注意力 + 一个下三角掩码**:在 softmax 之前用 `masked_fill` 把"未来位置"填 `-inf`,靠 `exp(-inf)=0` 让每个 token 只能看到自己和左侧,从而支持"预测下一个词"而不作弊;工程上再用 `nn.Module` 封装、加 batch 维和输出投影 `W_o`,就是真实 LLM 里每一层都在用的核心组件。

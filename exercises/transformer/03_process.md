# 03_multihead_attention.py 详细流程图解

> 配套脚本:`exercises/transformer/03_multihead_attention.py`
> 核心:**"多头" 怎么用一次张量重排,并行跑 N 个独立的 attention**。

## 全景:数据流(02 单头 → 03 多头)

```
   tokens ["The","cat","sat","on","the","mat"]
        │  ① 查表 + batch 维
        ▼
   x  (B=1, T=6, d=32)
        │  ② 一次性合并投影 W_qkv (d → 3d)
        ▼
   qkv (1,6,96) ──chunk(3)──► Q,K,V 各 (1,6,32)
        │
        │  ★③ 拆头: view + transpose
        ▼   把 32 维切成 4 头 × 8 维, 头维提到前面
   Q,K,V  (1, 4, 6, 8)          ← (B, nh, T, hd) 每个头独立
        │
        │  ④ 并行打分+掩码+softmax+加权V
        ▼   PyTorch 自动对 (B,nh) 批量矩阵乘
   out (1, 4, 6, 8)             attn (1,4,6,6) 每个头一份
        │
        │  ★⑤ 合头: transpose + reshape
        ▼   4 头 × 8 维 拼回 32 维
   out (1, 6, 32)
        │  ⑥ W_o 输出投影
        ▼
   out (1, 6, 32)               ← 形状和输入一样!
```

| 对比 | 02 单头 | 03 多头 |
|------|--------|--------|
| 投影 | W_q/W_k/W_v 三个 | 合成一个 `W_qkv`(d→3d) |
| 头数 | 1 | n_heads=4 |
| 关注模式 | 只能学一种 | 4 种并行 |
| 核心操作 | 直接算 | ★ 拆头 / 合头 重排 |
| attn 形状 | `(B,T,T)` | `(B, nh, T, T)` 每头一份 |

---

## 第②步:合并投影 W_qkv (61–80 行)

02 用三个 Linear,这里**合并成一个**再切开——一次大矩阵乘比三次小的更快:

```
   x(1,6,32) @ W_qkv(32, 96) = qkv(1,6,96)
                                    │ chunk(3, dim=-1)
                          ┌─────────┼─────────┐
                          ▼         ▼         ▼
                       Q(1,6,32) K(1,6,32) V(1,6,32)
```

---

## ★ 第③步:拆头 view + transpose(本篇最绕,82–87 行)

一行代码 `Q.view(B,T,nh,hd).transpose(1,2)` 做了两件事:

**3a. `view`:把"特征维 32"切成"4 头 × 8 维"** —— 纯逻辑切分,不改数据

```
  一个 token 的 32 维向量:
  [····································]   32维
   └─head0─┘└─head1─┘└─head2─┘└─head3─┘    切成 4 段, 每段 8 维

  Q: (1, 6, 32)  ──view──►  (1, 6, 4, 8)
                              B  T  nh hd
```

**3b. `transpose(1,2)`:把"头维"提到 T 前面** —— 让每个头的数据独立成块

```
  (1, 6, 4, 8)  ──transpose(1,2)──►  (1, 4, 6, 8)
   B  T  nh hd                        B  nh T  hd

  语义: 从"每个token持有4个头" 变成 "每个头持有完整6个token序列"
        → 后续矩阵乘时, 把 (B, nh) 都当 batch, 4个头一次性并行算
```

> 这就是"多头不是跑 N 次循环,而是一次张量运算"的关键:把头维塞进 batch 维的位置,让 PyTorch 的批量矩阵乘自动并行处理。

---

## 第④步:并行 attention(89–99 行,逻辑同 02)

每个头在自己的 8 维空间里独立做一遍 02 的 attention,只是 batch 维从 `(B)` 变成 `(B, nh)`:

```
  Q @ K.transpose(-2,-1) / √hd
  (1,4,6,8) @ (1,4,8,6) = scores (1,4,6,6)
          └ 对 (B=1, nh=4) 批量算, 每个头一张 6×6 分数表 ┘
        │ 因果掩码(所有头共用同一张 tril) + softmax
        ▼
  attn (1,4,6,6)  ──@ V(1,4,6,8)──►  out (1,4,6,8)
```

注意:`√hd` 用的是**头内维度 8** 而非 32——每个头是在自己的小空间里缩放。

---

## ★ 第⑤步:合头 transpose + reshape(101–104 行)

拆头的逆操作,把 4 个头的输出拼回 32 维:

```
  out (1,4,6,8)  ──transpose(1,2)──►  (1,6,4,8)  ──view──►  (1,6,32)
   B nh T hd                           B T nh hd              B T  d
                                          └ 4头×8维 拼回 32维 ┘

  ⚠ .contiguous(): transpose 只改了"视图"(stride), 内存还是乱的,
     view 要求内存连续 → 先 contiguous() 把数据真正重排一遍。
```

---

## 第⑥步:输出投影 W_o (106–107 行)

```
  out = self.W_o(out)    (1,6,32) → (1,6,32)
```

**这里 W_o 的作用比 02 更实**:它要把"4 个头各看各的"结果**融合**起来——某个维度可以同时参考多个头的输出。所以多头的 W_o 是真正在"综合各视角",不是走过场。

---

## 参数量 (145–151 行)

```
  W_qkv: d × 3d = 3d²
  W_o:   d × d  =  d²
  ─────────────────────
  合计:  4d² = 4 × 32² = 4096
```

**注意:头数 n_heads 不影响参数量!** 多头只是把同样的 d 维切开用,不增加权重——"免费"获得多视角。

---

## 可视化:4 个头并排 (165–194 行,需 `--draw`)

```
 ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
 │ Head 0 │ │ Head 1 │ │ Head 2 │ │ Head 3 │
 │ ◣ 下三角│ │ ◣      │ │ ◣      │ │ ◣      │
 │ 模式 A │ │ 模式 B │ │ 模式 C │ │ 模式 D │
 └────────┘ └────────┘ └────────┘ └────────┘
   都是因果(下三角), 但每头权重分布不同
```

即使是随机初始化,4 个头的注意力矩阵也各不相同(因为 W_qkv 各段权重不同);训练后它们会分化成不同的关注模式。

---

## 一句话总结

多头注意力 = **把 d_model 切成 n_heads 份,每份独立做一遍 02 的因果 attention,再拼回来过 W_o**;实现上不用循环,而是靠 `view + transpose` 把"头维"塞到 batch 位置(`(B,T,d)→(B,nh,T,hd)`),让一次批量矩阵乘并行算完所有头,算完再 `transpose + view` 拼回去;代价是**零额外参数**(仍是 4d²),收益是模型能同时学多种关注模式。

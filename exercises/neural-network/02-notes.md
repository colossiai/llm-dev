# 02 笔记

## 如何理解:神经网络训练靠"反向传播"?

### 一句话理解

> **反向传播 = "从 loss 倒推回去,告诉每个参数它该往哪边挪一点点"。**

---

### 拆开看:训练到底在干什么?

#### 训练的目标

模型有几百万个参数(W、b),它们一开始是随机的,预测必然乱七八糟。
**训练 = 慢慢挪参数,让预测越来越准 = 让 loss 越来越小。**

#### 核心难题

```
模型: y_hat = f( W1, W2, W3, ..., 几百万个参数 )
loss = (y_hat - y)²
```

问题:**几百万个参数,我该挪哪一个?挪多少?往哪挪?**

人脑无法手动调,机器也不能"试错"(试一遍要算几百万次,太慢)。

---

### 反向传播给出的答案

**对每个参数 W,算一个"梯度" `dL/dW`:**

| `dL/dW` 的意义 | 我该怎么做 |
|---|---|
| 是正数(W 增大 → loss 增大) | W 往**小**的方向挪 |
| 是负数(W 增大 → loss 减小) | W 往**大**的方向挪 |
| 接近 0 | 不挪 |
| 绝对值大 | 挪多一点 |
| 绝对值小 | 挪少一点 |

更新规则就一行:

```python
W -= lr * dL/dW   # lr 是学习率,控制每步多大
```

→ **关键问题变成:怎么算 dL/dW?**

---

### 为什么叫"反向"?

因为算梯度时,**必须从 loss(最后)往输入(最前)倒着算**。

#### 前向(forward):从输入到 loss

```
x ──Linear──> h_pre ──ReLU──> h ──Linear──> z ──Sigmoid──> y_hat ──> loss
                                                                       │
                                                                       └── 这里有"误差"
```

#### 反向(backward):从 loss 倒推

```
loss
  │
  ├──> 算 dL/dz       ← 第一步,误差还在最末端
  │
  ├──> 算 dL/dh       ← 把误差"反传"穿过 Linear
  │
  ├──> 算 dL/dh_pre   ← 把误差"反传"穿过 ReLU
  │
  └──> 算 dL/dW1      ← 误差最终落到第一层参数上
```

→ **每一步都用链式法则:`dL/dW1 = dL/dz × dz/dh × dh/dh_pre × dh_pre/dW1`**

---

### 关键直觉:链式法则 = "责任分摊"

假设最终 loss 偏高 10 分。这 10 分要分摊给"沿途经过的所有参数":

- 哪些参数对这一刻的输出影响大 → 分到更多责任 → 梯度大 → 该重点调整
- 哪些参数对输出影响小 → 分到少 → 梯度小 → 微调即可

**激活函数的导数 = "责任分摊的传递系数"**

```
dL/dh_pre = dL/dh × ReLU'(h_pre)
                    └──────────┘
                    "传过来的责任"乘以这个系数
```

---

### 回到 02 docstring 那句话

> "神经网络训练靠'反向传播', 每一步都要乘上激活函数的导数。
> 如果某个区域导数 ≈ 0, 那里就'传不动'梯度, 训练会卡住。"

现在能秒懂了:

- 反传时每穿过一层激活,都要 `× 激活函数的导数`
- 如果导数 = 0(比如 Sigmoid 在 |x| > 4 的位置),**那一站的责任直接归零**
- 责任传不到前面的层 → 前面的参数收不到梯度 → **训不动**

这就是**梯度消失(vanishing gradient)** 的物理原因,也是为什么 ReLU 取代 Sigmoid 成为主流(ReLU 在正半轴导数永远是 1,不会衰减)。

---

### 一段比喻

> **训练像一家公司在反思业绩**:
>
> - **forward** = "今年怎么干的"(从招工→生产→销售→收入)
> - **loss** = "今年亏了多少钱"
> - **backward** = "亏钱的责任分摊到每个部门、每个员工"
>   - 越是直接接触客户的部门(后层),先算责任
>   - 然后沿着流程倒推,算上游(前层)的责任
>   - 每经过一道工序,责任要乘上"这道工序的传递系数"(= 激活函数导数)
>   - 如果某道工序传递系数是 0(比如打包车间睡着了),后面所有上游就甩锅不动了 → 梯度消失
> - **opt.step()** = "根据各自分到的责任,每个人调整明年的工作量"

## 误解纠正:"LLM 没有用到这些激活函数, 只是用 cross-entropy"

这是一个常见误解 —— **激活函数和 cross-entropy 是两个完全不同的东西, LLM 两者都用。**

### 两者的角色完全不同

| | 激活函数 | Cross-Entropy |
|---|---|---|
| **位置** | 在网络**内部每一层**后面 | 整个模型**最末端** |
| **作用** | 把线性层"折弯",让网络能学非线性 | 衡量"预测分布"和"真实标签"差多少 |
| **类比** | 中间车间的"工序" | 终点的"考试评分标准" |
| **是否可同时存在** | ✓ 是 — 它们解决不同问题 | ✓ 是 |

→ **LLM 是同时用两者的:激活函数在网络中间,cross-entropy 在最末端当 loss。**

---

### LLM 里到底用了哪些激活函数?(打开源码看)

#### GPT-2 / GPT-3(OpenAI)

```python
# 简化版的 Transformer FFN 块
def feed_forward(x):
    x = Linear1(x)
    x = GELU(x)       # ← 激活函数!
    x = Linear2(x)
    return x
```

→ **每个 Transformer block 都有 GELU**

#### LLaMA / LLaMA 2 / LLaMA 3(Meta)

```python
def swiglu_ffn(x):
    return Linear2( SiLU(Linear_gate(x)) * Linear_up(x) )
                    # ↑ SiLU 激活!
```

→ **用的是 SiLU(也叫 Swish),组合成 SwiGLU**

#### Qwen / Mistral / DeepSeek

→ 全都用 **SwiGLU(基于 SiLU)**

#### 还有一个"隐藏"的激活:Softmax

注意力机制里:

$$\text{Attention} = \text{softmax}\left(\frac{QK^T}{\sqrt{d}}\right) V$$

**Softmax 也算一种激活函数**,它把任意分数转成"概率分布"。LLM 里每一层 Attention 都用一次。

---

### Cross-Entropy 的角色:训练目标

```
LLM 输出: 词表中每个 token 的概率 (用 softmax 算)
                ↓
       Cross-Entropy Loss = -log(真实下一个 token 的概率)
                ↓
       loss.backward() → 反传梯度 → 更新所有参数(包括 GELU/SiLU 后面的 Linear)
```

**Cross-Entropy 不能替代激活函数**,它只在最末端用一次,告诉网络"你预测错了多少"。
**激活函数在网络内部每层都用**,负责让网络能学复杂关系。

---

### 一张图对比

```
                              LLM 训练时的数据流

input tokens
    │
    ▼
┌─────────────────────────────────┐
│  Transformer Block × N (~96层)  │
│  ┌───────────────────────────┐  │
│  │ Self-Attention            │  │
│  │   └─ softmax  ← 激活      │  │   ← 激活函数在这里
│  │ FFN                       │  │     用了很多次!
│  │   └─ GELU/SiLU/SwiGLU     │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
    │
    ▼
output logits (vocab_size 维)
    │
    ▼
softmax → 概率分布
    │
    ▼
Cross-Entropy Loss  ← 损失函数在这里
                       (训练时才用,推理时不用)
```

02 docstring 里其实已经标注了:

```
GELU       GPT/BERT 用的, 比 ReLU 平滑
SiLU       LLaMA 用 (也叫 Swish), 等于 x * sigmoid(x)
```

这两个是现代 LLM 的"心脏激活"。**学这些不是过时知识,而是 LLM 工作原理的核心组件之一。**

---

### 一句话总结

> 激活函数和 cross-entropy **不是替代关系,而是搭档关系**:
>
> - 激活函数(GELU/SiLU)→ 让网络**有能力**学复杂模式(每层都要用)
> - Cross-entropy → 给网络一个**目标**告诉它学得对不对(只在末端用一次)
>
> 一个 LLM 缺了任何一个都跑不起来。

# 01 笔记

## `step()` 的作用 — 是把 z 转成 bool 吗?

```python
def step(z):
    return (z > 0).astype(np.float64)
```

**不完全是。** 这个函数最终返回的是 **float(1.0 或 0.0)**,bool 只是中间步骤。

### 拆解执行

```python
z = np.array([1.5, -0.3, 0.0, 2.7])
```

**Step 1**:`z > 0` — 比较运算,返回 bool 数组

```
array([ True, False, False,  True])
```

**Step 2**:`.astype(np.float64)` — 把 bool 转 float

```
array([1., 0., 0., 1.])
```

最终输出是 float。

### 这是什么函数?

**Step Function(阶跃函数 / Heaviside)**,感知机最原始的激活函数:

```
       │
   1   │  ─────────
       │
       │
   0───┼─────────── z
       │
       │
```

- `z > 0` → 1(预测正类)
- `z ≤ 0` → 0(预测负类)

### 为什么要转成 float,不直接用 bool?

下一行马上要做减法运算:

```python
err = y[i] - y_pred   # y[i] 是 float, y_pred 也得是数值
W += lr * err * X[i]  # 这里 err 必须能参与乘法
```

虽然 numpy 里 bool 也能做算术(True=1, False=0),但显式转 float 更清晰、和后续计算的 dtype 一致。

### 一句话总结

> `step(z)` = 阶跃激活函数。输入数值 z,输出 1.0(正)或 0.0(负)。中间用 bool 比较,最后转 float 方便和参数做运算。

## `@` 是 numpy 的符号吗?需要 pytorch 支持吗?

`z = W @ X[i] + b` 是矩阵线性变换吧,`@` 是 numpy 支持的符号吗?需要 pytorch 支持吗?

### `@` 的真相

- `@` 是 **Python 3.5+ 内置运算符**(PEP 465 引入,2015 年)
- 它本身没有功能,只是**调用对象的 `__matmul__` 方法**
- numpy / pytorch / jax / tensorflow 都各自实现了 `__matmul__`,所以都能用

```python
# 都能用, 不需要任何特殊 import
np.array([1, 2]) @ np.array([3, 4])         # numpy
torch.tensor([1, 2]) @ torch.tensor([3, 4]) # pytorch
[1, 2] @ [3, 4]                              # ❌ list 没实现, 报错
```

### 在 01 里到底是什么运算?

```python
W = np.array([-0.5, -0.5])    # shape (2,)  — 1D 向量
X[i] = np.array([1.2, -1.8])  # shape (2,)  — 1D 向量
z = W @ X[i] + b
```

**严格来说,这里不是"矩阵乘法",是 dot product(点积)**,因为两边都是 1D:

```
W @ X[i] = W[0]*X[i][0] + W[1]*X[i][1]
         = (-0.5)*1.2 + (-0.5)*(-1.8)
         = 0.3   ← 标量
```

### `@` 在不同维度组合下做不同事

| W shape | x shape | `W @ x` | 行话 |
|---------|---------|---------|------|
| (n,) | (n,) | scalar | dot product / 点积 |
| (m, n) | (n,) | (m,) | matrix-vector(矩阵向量乘) |
| (m, n) | (n, k) | (m, k) | matrix multiplication(矩阵乘法) |
| (b, m, n) | (b, n, k) | (b, m, k) | batched matmul |

→ **同一个 `@` 符号,numpy/pytorch 根据形状自动选规则。**

### 那"线性变换"的说法对不对?

也对,从更高的视角看:

$$
z = W \cdot x + b
$$

这是**仿射变换(affine transformation)**:

- `W @ x` 部分 = **线性变换**(旋转/缩放/投影)
- `+ b` 部分 = **平移**

在感知机里 W 是 1D,等价于"把 2D 输入投影到 1 个标量"——也算线性变换的特例(投影到一维)。

### 一句话总结

> `@` 是 Python 内置运算符,numpy/pytorch 都实现了。本句里 W 和 X[i] 都是 1D 向量,所以 `W @ X[i]` 是**点积**,得到一个标量,再加 bias = 仿射变换的输出。

## 01_perceptron.py 在做什么?(给零 ML 基础读者)

具体问题:
- 输入是一组点?
- 输出是一条直线区分这组点吗?
- 用的什么算法?普通梯度下降?
- 为什么 W 是 1D 向量?
- y 是预期正确答案吗?为什么 `error = y[i] - step(W @ X[i] + b)`?

### 一、整体目标:学会区分两类点

**输入**:一堆带颜色的 2D 点

- 100 个点,每个点有两个坐标 `(x1, x2)`
- 蓝色 50 个(标签 = 0),红色 50 个(标签 = 1)

**输出**:一条直线 `W[0]·x1 + W[1]·x2 + b = 0`

- 直线一边 → 预测为蓝色
- 直线另一边 → 预测为红色

→ **目标:让这条直线尽量把两种颜色分开**。

---

### 二、用的算法:不是梯度下降,是"感知机更新规则"(1958 年发明)

这是一个比梯度下降更古老、更"原始"的算法,叫 **Perceptron Update Rule**:

```python
if err != 0:                  # 只在预测错的时候更新
    W += lr * err * X[i]      # 朝正确方向"拉"一点
    b += lr * err
```

**和梯度下降的区别**:

| | 感知机规则 | 梯度下降 |
|---|---|---|
| 损失函数 | 没有(不算梯度) | 有(MSE/BCE/...) |
| 何时更新 | 只在预测**错**时 | 每次都更新 |
| 激活函数 | step(阶跃,不可导) | sigmoid/ReLU(可导) |
| 来源 | Rosenblatt 1958 | 现代 NN |

**直觉**:感知机更新规则像"老师批改作业"——只在学生写错时打回去修改,写对就不管。

---

### 三、为什么 W 是 1D 向量?

因为这是个**最简单的一对一映射**:

```
输入:  2 个数   (x1, x2)
        ↓
神经元:  W @ x + b   ←  W 有 2 个权重就够了
        ↓
输出:  1 个数(再经过 step 变成 0 或 1)
```

- 输入特征数 = 2 → W 需要 2 个数 → shape `(2,)` 的 1D 向量
- 输出类别 = 二分类(0 或 1) → 只需 1 个输出

**如果改成 3 分类输出 3 个数**,W 就会是 `(3, 2)` 矩阵了。

---

### 四、y 和 error 的含义

#### y 是"标准答案"(数据标签)

```python
y = np.hstack([np.zeros(50), np.ones(50)])
#               前 50 个是 0      后 50 个是 1
```

→ `y[i]` 就是第 i 个点的**真实颜色**(标签),来自数据集,**不是算法算出来的**。

#### error 的三种情况

```python
y_pred = step(W @ X[i] + b)   # 模型的猜测: 0 或 1
err    = y[i] - y_pred         # 真实 - 猜测
```

`err` 只可能是三个值:

| y[i](真实) | y_pred(预测) | err = y - y_pred | 含义 |
|---|---|---|---|
| 0 | 0 | **0** | ✓ 猜对了,不动 |
| 1 | 1 | **0** | ✓ 猜对了,不动 |
| 1 | 0 | **+1** | ✗ 应该是 1 却猜 0,**W 要朝 x 方向"拉"** |
| 0 | 1 | **-1** | ✗ 应该是 0 却猜 1,**W 要朝远离 x 方向"推"** |

然后更新:

```python
W += lr * err * X[i]
```

- `err = +1`:`W` 加上一点 `X[i]` → 下次同样输入,`W @ X[i]` 会更大,更可能预测为 1
- `err = -1`:`W` 减掉一点 `X[i]` → 下次同样输入,`W @ X[i]` 会更小,更可能预测为 0
- `err = 0`:不动

---

### 五、把整个流程串起来的故事

1. **造一堆点**:左上角 50 个蓝点,右下角 50 个红点
2. **画一条乱七八糟的初始直线**(W 随便初始化)
3. **挨个看每个点**:
   - 如果直线把它分对了 → 啥也不干
   - 如果分错了 → 把直线**朝那个点的方向偏一点**(让下次同样的点更容易分对)
4. **跑 30 轮**,直线慢慢转到正确位置
5. **输出**:学到的 W 和 b,以及决策边界图

---

### 一句话总结

> **感知机 = 一条会自己挪位置的直线。每看到一个分错的点,就把直线朝"让这个点分对"的方向偏一点;看到分对的就不动。重复几轮,直线就找到能把两类点分开的位置。**

## 确认理解:x1、x2、y 各代表什么?

- 所以 x1 是横轴,x2 是竖轴,y 是 label(真实数据)?

完全正确 ✓

| 符号 | 含义 | 在代码里 |
|------|------|---------|
| `x1` | 横轴坐标(feature 1) | `X[i][0]` |
| `x2` | 纵轴坐标(feature 2) | `X[i][1]` |
| `y` | 标签 / 真实类别(0 或 1) | `y[i]` |

代码中的对应:

```python
X = np.vstack([X0, X1])   # shape (100, 2)
                          #         │   └── 每个点 2 个特征 (x1, x2)
                          #         └── 100 个点
y = np.hstack([...])      # shape (100,)
                          #         └── 100 个标签 (0 或 1)
```

画图时也是这样:

```python
ax.scatter(X0[:, 0], X0[:, 1], ...)   # 第 0 列当 x 轴, 第 1 列当 y 轴
ax.set_xlabel("x1")
ax.set_ylabel("x2")
```

### 易混点提示

ML 里 **"y"** 这个字母有歧义,容易和图的"竖轴 y"搞混:

- 在数学/绘图里:`y` 通常指**竖轴坐标**
- 在 ML 里:`y` 几乎总是指**标签 / 目标值**(target / label)

所以你看到 `y[i] = 1` 时,它的意思是"第 i 个点的真实类别是 1",**和它在图上的纵坐标(x2)没有任何关系**。
